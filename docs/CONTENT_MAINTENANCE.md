# 内容与首页维护

## 本次内容

- 网站案例：`content/projects/zhuqing-studio.mdx`
- 开发复盘：`content/garden/building-zhuqing-studio.mdx`
- 两篇内容通过 `relations` 关联，并由现有公开内容加载器读取。

## 首页三种信息

- 此刻：在 `src/data/now.ts` 维护正在创造、正在学习及实际更新时间。日期代表内容更新时间，不应自动取当天日期；思考文案沿用 `src/i18n/translations.ts` 的 `now_thought`，修改时同步更新快照日期。
- 精选项目：由项目 MDX 的 `featured: true` 标记决定。
- 最新记录：从已发布笔记按 `date` 降序取第一篇，与精选标记无关。

## 添加项目

AI 助手案例保留专用图解。其他项目使用自己的 Users、Principles、Architecture、Workflow 和 Reflection 章节，空列表不会显示。Overview、Challenge 和 Status 用于顶部概述。

## 内容边界

只写能够核实的实现、决策和结果。线上部署、跨设备同步、效率提升与读者反馈需有独立证据。生活记录现可整理为独立文章草稿并导出发布包，加入仓库与上线仍由维护者完成。

## 从记录整理文章

1. 打开一条生活记录，点击「整理为文章」。再次点击会继续该来源的已有草稿。
2. 补充标题、摘要、分类、日期和正文。草稿自动保存到当前浏览器，可从「生活 → 文章草稿」继续。
3. 在「预览文章」检查内容，再导出 ZIP。包内包含 `content/garden/*.mdx`、`public/images/articles/*` 和说明文件；只打包正文引用的附件。
4. 合入网站同名目录，检查后通过现有构建与发布流程上线。导出的文章元数据为 `published`；如需暂缓，可改为 `draft`。

导出内容使用 `format: markdown`，按普通 Markdown 渲染，不执行正文中的 JSX。它与本机预览共用 Markdown 渲染器，并自动适配 `/images/` 的部署子路径。已有手写 MDX 继续走原有渲染方式。

草稿的文字、图片、来源版本随全部生活备份导出，旧版备份仍可导入。导入沿用只新增、不覆盖规则；同编号本机记录优先保留。来源被修改或删除不会覆盖草稿。两页同时修改同一草稿时会提示保存冲突，可以先备份当前编辑，再重新打开。

「已导出」仅表示已生成文件并发起下载，不表示上线；继续编辑后回到草稿状态。本机数据不跨设备同步，清除浏览器数据前请备份。

## 验证

每周回顾入口为「生活 → 每周回顾」。按当前设备时区，以周一零点至下一周周一零点汇总本机记录，分别展示新建记录、最近修改的旧记录和文章草稿。它不是完整的历史日志；一条旧记录再次修改后，其最近修改时间会变化。回顾本身不计入记录数量。

回顾文字手动保存，每周一份，可切换周查看；它与文章草稿一同纳入生活备份，保留现有的版本冲突保护。它不会自动同步项目仓库或云端进展。

运行 `npm run life:verify`、`npm run articles:verify`、`npm run weekly:verify`，并用 `GITHUB_PAGES=true` 构建后执行 `npm run site:verify`。检查覆盖备份兼容、图片导出、元数据与 Markdown 完整性、连续保存与失败重试、每周统计边界，以及站内链接。
