## Overview
AI 智能助手系统不是一个只负责回答问题的聊天机器人，而是一套面向个人长期工作的协作基础设施。它理解人的意图，组织可确认的行动计划，调用工具完成任务，并把有价值的过程与结果沉淀为可复用的知识。

## Challenge
今天的 AI 工具擅长生成答案，却经常与真实工作流、个人知识和长期上下文彼此割裂。这个系统希望解决的问题是：怎样让 AI 从一次性对话走向持续协作，在减少重复劳动的同时，让每一步可见、可控，并保留人的最终判断。

## Users
- 需要同时处理学习、创作与项目任务的个人知识工作者
- 希望把零散 AI 工具组织成稳定工作流的创造者
- 重视长期知识积累，而不只追求即时答案的学习者

## Use Cases
- 将模糊想法整理为可执行的研究或创作计划
- 调用搜索、文档和自动化工具完成多步骤任务
- 从任务过程提炼笔记、决策依据与可复用方法
- 基于个人知识上下文继续后续工作，而不是每次重新开始

## Principles
- 人始终拥有目标、关键步骤与最终结果的决定权
- 计划、工具调用和结果来源应当清晰可追踪
- 长期记忆必须可管理、可修正，也可以被遗忘
- 模块之间保持松耦合，便于替换模型与工具

## Architecture
- 用户交互层：目标输入、计划确认、过程反馈与结果呈现
- 任务编排层：意图理解、计划拆解、状态管理与结果整合
- 工具能力层：网页研究、文档处理与知识检索
- 上下文数据层：项目记忆、来源引用与执行记录
- 安全控制面：权限确认、失败恢复与行为审计

## Data Architecture
- 输入数据：用户目标、消息、文件、链接与明确限制
- 当前上下文：当前任务、限制条件、已确认计划与相关资料
- 项目数据：项目、任务、计划、决策与当前进度
- 知识数据：文档、笔记、来源、引用与可复用结论
- 长期记忆：已确认偏好、重要事实、历史决策与可复用方法
- 执行记录：用户确认、工具调用、执行结果与错误信息
- 记忆治理：用户可以查看、修正、删除、导出并设置保留期限

## Core Data Model
- 用户与项目：用户拥有项目，项目作为任务、会话、资料和项目记忆的边界
- 任务与步骤：任务保存目标、状态和计划版本，任务步骤保存顺序、输入、输出与重试状态
- 会话与消息：会话可以关联项目或具体任务，消息保留角色、内容与时间信息
- 确认记录：关键决策和外部操作单独保存请求内容、用户决定与决定时间
- 工具执行：每次工具调用属于具体步骤，保存请求、结果、错误、耗时与幂等标识
- 资料与引用：资料保存来源和完整性信息，引用把消息或工具结果连接到可核验位置
- 记忆条目：候选与正式记忆使用状态区分，并保留作用范围、来源任务与失效时间
- 审计事件：所有重要状态变化保存触发者、事件类型、目标实体和变化前后内容

## Execution Lifecycle
- 新建任务：接收目标、限制条件、可用资料与期望结果
- 澄清上下文：补齐会影响计划或结果的关键信息
- 形成计划：拆解步骤、依赖关系、所需工具、风险与确认点
- 等待确认：关键决策、外部操作和高影响行为必须由用户批准
- 准备执行：检查上下文、权限、工具可用性与恢复检查点
- 逐步执行：按计划推进任务并记录每个步骤、工具调用和阶段结果
- 异常处理：信息不足时等待补充，执行失败时重试、替代或回滚
- 整理验收：汇总结果、来源、不确定性和仍待解决的问题
- 完成归档：用户验收后保存执行记录，并生成需要再次确认的记忆候选

## Security and Permissions
- 权限范围：每次操作同时绑定发起者、动作类型、目标资源和有效时间
- 只读观察：搜索、阅读、检索与总结可在明确的数据范围内自动执行
- 低风险可逆：草稿、未共享文档和本地整理需要可预览、可撤销并保留恢复快照
- 对外代表用户：发送、发布、分享、邀请和预约必须在行动时展示具体内容与对象并请求确认
- 高影响或敏感：删除、权限变更、敏感资料外发和高风险执行需要强确认，部分操作交由用户亲自完成
- 禁止边界：绕过安全限制、泄露凭证、隐蔽冒充和无范围批量操作直接拒绝
- 执行控制：工具调用设置最小权限、超时、重试预算、幂等标识与结果回执
- 审计要求：保存权限判断、用户决定、执行结果、失败原因与恢复动作

## Technical Architecture
- 部署策略：第一版采用 Web 客户端、模块化应用 API 和独立异步 Worker，不提前拆分大量微服务
- 接入层：统一处理身份与会话、请求校验、限流、超时和任务状态事件推送
- 应用核心：对话、任务编排、权限策略、上下文与记忆作为同一后端中的清晰模块
- 异步执行：耗时任务进入队列，由调度器和 Worker 按步骤执行、重试并从检查点恢复
- 工具运行时：工具适配层统一处理调用协议、最小权限、超时、幂等与资源隔离
- 数据服务：关系数据库保存业务事实，向量索引支持语义检索，对象存储保存文件与产物，缓存保存短期状态
- 模型接入：模型网关负责路由、预算、降级和供应商切换，避免业务逻辑绑定单一模型
- 外部连接：网页、文档、知识与自动化工具通过统一连接器接入
- 可观测性：任务 ID 贯穿请求、队列、执行和结果，统一采集日志、指标、链路、审计与告警
- 演进原则：只有负载、团队规模或故障隔离真正需要时，才把逻辑模块拆成独立服务

## Product Information Architecture
- 核心原则：项目是长期容器，任务是工作对象，对话是理解和推进任务的主要交互方式
- 项目首页：创建项目、查看状态、继续最近工作，不承载复杂任务执行细节
- 协作工作台：统一呈现目标、对话、任务计划、用户确认、执行进度和最终结果
- 工作台导航：左侧组织项目页面和任务列表，让用户随时知道自己正在处理哪个任务
- 协作主区：中间区域优先展示当前对话、可调整计划、关键确认和结果，不持续堆叠工具日志
- 上下文检查器：右侧按需查看本次上下文、资料来源、引用和待确认记忆
- 资料页面：管理文件、链接、来源、引用关系、处理状态与任务产物
- 记忆页面：管理候选和已确认记忆的内容、范围、来源、修正、删除与过期时间
- 活动记录：集中呈现用户确认、工具调用、状态变化、错误、恢复动作和审计证据
- 工具与设置：管理连接器、权限范围、模型偏好、通知与数据保留策略
- 界面约束：执行细节默认折叠，只有影响用户判断的信息进入工作台主视野

## Workspace Interaction States
- 提出目标：用户说明目标、资料、限制条件和期望结果，系统只追问会影响计划的关键信息
- 确认计划：系统展示步骤、工具、来源范围、风险与确认点，用户可以调整后再批准执行
- 任务执行：工作台呈现当前步骤、阶段结果、引用与异常状态，同时保留暂停、补充信息和改变方向的入口
- 结果验收：系统汇总产物、来源、不确定性和未完成事项，由用户决定是否通过、继续修改或保存归档
- 记忆确认：任务中发现的长期信息只作为候选出现，必须经过用户确认后才进入项目记忆
- 状态原则：界面围绕当前需要用户理解或决定的事情变化，不把底层工具日志直接堆给用户

## Workflow
- 理解意图：识别目标、限制条件和所需上下文
- 形成计划：把复杂目标拆成可查看、可调整的步骤
- 人工确认：在外部操作或关键决策前请求确认
- 调用工具：执行搜索、处理文件或触发自动化流程
- 整理结果：解释做了什么、产生了什么以及仍有哪些不确定性
- 沉淀知识：把有长期价值的结论连接到个人知识系统

## MVP
- 统一的对话与任务入口
- 可查看和确认的任务计划
- 三类基础工具：网页研究、文档处理、知识检索
- 项目级上下文与可编辑记忆
- 完整的执行记录和失败恢复提示

## Reflection
技术的价值不只是自动完成任务，也在于帮助人获得更多创造空间。一个好的智能助手不应该替人决定，而应该让人的意图更清晰、行动更连贯、知识更有积累。
