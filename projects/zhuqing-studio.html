用一个持续维护的个人网站，连接项目实践、公开笔记与日常记录，探索适合长期积累的数字空间。

要解决的问题

个人网站既要让初次访问的人理解创作者在做什么，也要容纳尚未整理完成的学习与生活记录。如果所有内容都直接面向访客，零散素材会打断阅读；如果只保留完成的作品，积累过程又难以留下。项目需要同时照顾公开表达与日常记录，并让两者的边界足够清楚。

设计方向

竹青小筑围绕创造、求知与观照组织内容。主导航收敛为项目、笔记、生活和关于，让技术实践与个人兴趣有各自的位置。首页用简短介绍、当前近况、精选项目和最新笔记提供入口，细节留给内页展开。

当前进展

仓库已具备首页、项目案例、公开笔记、主题索引、知识网络、时间线与本机生活记录等实现。本次补充网站案例与开发复盘，并将首页近况独立维护、最新笔记按发布日期选取。本机记录尚未与公开文章形成自动发布流程，也不等于跨设备同步；云端知识增强的实际部署状态需单独验证。这里记录实现范围，不将功能存在等同于线上可用性或用户效果。

01

Practice

为谁而做

  • 技术同行：了解项目背景、实现方式与工程取舍
  • 潜在合作伙伴：判断创造方向与解决问题的方式
  • 长期读者：沿着笔记与时间线观察持续积累
  • 网站维护者：记录素材、整理内容并维护自己的数字空间
02

Practice

设计取舍

  • 内容优先：页面为真实项目与笔记服务，不用栏目数量代替内容厚度
  • 安静阅读：保持清晰层级，把较长的设计细节放在可展开区域
  • 数据有边界：公开文章与本机记录分别管理
  • 小步演进：复用已有内容加载器与组件，避免为每篇案例复制页面
03

Practice

实现结构

  • 页面层：Next.js App Router 组织项目、笔记、生活与关于等路由
  • 内容层：仓库中的 MDX 保存项目与公开笔记，通过统一加载器解析元数据
  • 关联层：主题索引与知识网络把已发布内容连接起来
  • 本机记录层：生活记录使用 IndexedDB 保存文字和图片，支持备份与导入导出
  • 构建层：生成静态站点，并支持 GitHub Pages 的子路径配置
04

Practice

从记录到公开阅读

  • 随手记录：在生活记录中保存文字、链接与图片
  • 保留副本：通过 JSON 备份或 Markdown 导出带走记录
  • 整理文章：当前仍需手动整理为仓库中的 MDX，并补充摘要、分类与关系
  • 公开阅读：已发布内容进入列表、详情页与知识索引
  • 持续更新：用明确日期维护首页近况，用新的复盘补充实践过程
05

Reflection

阶段反思

当前最值得继续验证的是：记录能否被定期整理成可读、可关联的内容。页面和功能已经提供了容器，下一步应减少整理成本，并积累带有问题、取舍与结果的真实案例。网站的成长需要从内容中被看见。
