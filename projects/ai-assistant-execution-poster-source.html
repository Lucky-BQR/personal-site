TASK EXECUTION LIFECYCLE / v0.1
STATE · CONTROL · RECOVERY

一张图讲清 AI 智能助手 如何安全地推进一个任务

任务不是一句提示词，而是一组可追踪的状态；每次推进都有条件、责任人与恢复路径

USER CONTROL
修改目标确认计划批准操作暂停 / 终止验收结果
用户始终拥有最终决定权
PRIMARY PATH
01DRAFT新建任务

接收目标、限制、资料与期望结果

02CLARIFYING澄清上下文

只补齐会影响结果的关键信息

03PLANNED形成计划

拆解步骤、依赖、工具与风险

04CONFIRMING等待确认

关键决策与外部操作由用户批准

05READY准备执行

权限、上下文和工具均已就绪

06RUNNING逐步执行

记录状态、工具调用与阶段结果

07REVIEWING整理验收

汇总结果、来源与不确定性

08COMPLETED完成归档

用户验收，形成记录与记忆候选

EXCEPTION PATH
BLOCKED等待补充

信息不足、权限缺失或需要新的用户判断

FAILED执行失败

保留错误现场，按重试、替代或回滚处理

PAUSED / CANCELLED暂停或终止

用户可随时暂停；终止后保留已完成记录

补齐信息 → 回到准备执行恢复成功 → 从安全检查点继续用户决定 → 恢复或结束任务
RECOVER TO SAFE CHECKPOINT
STATE RULES状态机约束
01 · SOURCE OF TRUTH状态是唯一事实源

界面、执行器和记录读取同一任务状态。

02 · TRACEABILITY每次变化可追踪

记录触发者、时间、原因与前后状态。

03 · SAFE EXECUTION工具调用属于步骤

设置权限、超时、重试预算与幂等标识。

04 · VISIBLE FAILURE失败不得静默吞掉

明确展示影响、恢复方案和所需决定。

原则：AI 可以推动进度，但不能绕过确认、隐藏失败或替用户完成关键判断。竹青小筑 · AI Systems
